# Acesso SSH ao Parrot pelo SSL-VPN Web Portal do FortiGate 50E

## Problema inicial

O serviço SSH estava funcionando normalmente:

```text
Server listening on 0.0.0.0 port 22.
Server listening on :: port 22.
```

Porém, o acesso pelo FortiGate apresentava:

```text
Unable to negotiate ... no matching key exchange method found.
Their offer:
diffie-hellman-group-exchange-sha256,
diffie-hellman-group-exchange-sha1,
diffie-hellman-group14-sha1,
diffie-hellman-group1-sha1
```

## Diagnóstico

O OpenSSH moderno do Parrot aceitava apenas algoritmos mais recentes:

```text
mlkem768x25519-sha256
sntrup761x25519-sha512
curve25519-sha256
ecdh-sha2-nistp256
ecdh-sha2-nistp384
ecdh-sha2-nistp521
```

O cliente SSH integrado ao FortiGate 50E utiliza algoritmos legados. Por isso, não havia um algoritmo de troca de chaves em comum.

Depois de corrigir o KEX, surgiu um segundo erro:

```text
no matching host key type found.
Their offer: ssh-rsa,ssh-dss
```

Isso indicou que também era necessário permitir temporariamente o algoritmo de chave de host `ssh-rsa`.

## Solução aplicada

### 1. Verificar se o Parrot ainda suporta o algoritmo legado

```bash
sudo sshd -T \
  -o "KexAlgorithms=+diffie-hellman-group-exchange-sha256" \
  2>&1 | grep -i kex
```

O resultado confirmou que o algoritmo ainda era suportado pelo Open, mas estava desabilitado por padrão.

### 2. Criar uma configuração de compatibilidade

```bash
sudo nano /etc/ssh/sshd_config.d/99-fortigate-compat.conf
```

Conteúdo do arquivo:

```text
# Compatibilidade com o cliente SSH legado do FortiGate 50E
KexAlgorithms +diffie-hellman-group-exchange-sha256
HostKeyAlgorithms +ssh-rsa
```

O caractere `+` adiciona os algoritmos à configuração existente sem remover os algoritmos modernos.

### 3. Validar e recarregar o SSH

```bash
sudo sshd -t
sudo systemctl reload ssh
```

Se o comando `sshd -t` não retornar nenhuma mensagem, a sintaxe está correta.

### 4. Confirmar a configuração ativa

```bash
sudo sshd -T | grep -iE '^(kexalgorithms|hostkeyalgorithms)'
```

O resultado deve conter:

```text
diffie-hellman-group-exchange-sha256
```

e:

```text
ssh-rsa
```

### 5. Acompanhar os logs

Durante uma nova tentativa de acesso pelo bookmark do FortiGate:

```bash
sudo journalctl -u ssh -f
```

O acesso bem-sucedido deve gerar mensagens semelhantes a:

```text
Accepted password for admin from 192.168.1.1
pam_unix(sshd:session): session opened for user admin
```

## Resultado

O acesso SSH ao Parrot pelo bookmark do SSL-VPN do FortiGate foi restabelecido.

A correção exigiu habilitar:

- `diffie-hellman-group-exchange-sha256` para a troca de chaves;
- `ssh-rsa` para a chave de host do servidor.

## Observações de segurança

Esses algoritmos são usados apenas por compatibilidade com o cliente SSH antigo do FortiGate.

- `ssh-rsa` utiliza um algoritmo legado baseado em SHA-1.
- Evitar habilitar `ssh-dss`.
- Não expor a porta SSH diretamente à Internet.
- Restringir o acesso à porta `22` somente às redes ou dispositivos confiáveis.
- Sempre que possível, atualizar o FortiOS/FortiGate.
- Como alternativa mais segura, utilizar a VPN em modo túnel e conectar usando o cliente SSH moderno do próprio computador.

## Como desfazer a alteração

Para remover a compatibilidade:

```bash
sudo rm /etc/ssh/sshd_config.d/99-fortigate-compat.conf
sudo sshd -t
sudo systemctl reload ssh
```
