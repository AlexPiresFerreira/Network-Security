## Objetivo

Disponibilizar listas de IPs e domínios em um repositório GitHub para que o FortiGate possa consultá-las periodicamente e utilizá-las em políticas de segurança.

> **Importante:** nunca coloque o PAT diretamente na URL ou dentro dos arquivos. O token deve ser informado somente no campo de autenticação do conector no FortiGate.

---

## 1. Estrutura do repositório

Exemplo de repositório:

```text
AlexPiresFerreira/Fortigate
```

Arquivos recomendados:

```text
allow-ip.txt
blocked-domains.txt
```

---

## 2. Arquivo de IPs

### Nome do arquivo

```text
allow-ip.txt
```

### Conteúdo

Utilize somente endereços IP ou redes CIDR, um por linha:

```text
1.1.1.1
3.3.3.3
192.168.10.0/24
```

Não utilize:

```text
# Lista de IPs
www.uol.com.br
https://1.1.1.1
```

### URL Raw do GitHub

```text
https://raw.githubusercontent.com/AlexPiresFerreira/Fortigate/main/allow-ip.txt
```

Esse arquivo deve ser usado em um conector do tipo:

```text
IP Address Threat Feed
```

---

## 3. Arquivo de domínios bloqueados

### Nome do arquivo

```text
blocked-domains.txt
```

### Conteúdo

Utilize somente nomes de domínio, um por linha:

```text
uol.com.br
www.uol.com.br
gpoaccess.com
```

Não utilize:

```text
http://uol.com.br
https://gpoaccess.com/
1.1.1.1
```

### URL Raw do GitHub

```text
https://raw.githubusercontent.com/AlexPiresFerreira/Fortigate/main/blocked-domains.txt
```

Quando disponível na versão do FortiOS, esse arquivo deve ser usado em um conector do tipo:

```text
Domain Name Threat Feed
```

---

## 4. Criação do PAT no GitHub

Acesse:

[GitHub — Personal Access Tokens](https://github.com/settings/tokens)

Crie um token com as seguintes configurações:

- **Tipo:** Fine-grained personal access token;
- **Repository access:** somente o repositório `AlexPiresFerreira/Fortigate`;
- **Repository permissions:**
  - **Contents:** `Read-only`;
- Demais permissões: não conceder.

Após criar o token:

1. Copie o PAT imediatamente;
2. Armazene-o em um gerenciador de senhas;
3. Não salve o token em arquivos públicos;
4. Não envie o token por chat ou e-mail;
5. Anote a data de expiração.

> O GitHub exibe o valor completo do PAT somente no momento da criação. Depois disso, ele não pode ser recuperado. Se for perdido, será necessário criar outro.

---

## 5. Configuração da autenticação no FortiGate

No conector do Threat Feed, habilite:

```text
HTTP Basic Authentication
```

Preencha:

```text
Username: AlexPiresFerreira
Password: SEU_PAT
```

A senha deve ser o PAT completo, normalmente iniciado por:

```text
github_pat_...
```

A URL deve permanecer sem o token:

```text
https://raw.githubusercontent.com/AlexPiresFerreira/Fortigate/main/allow-ip.txt
```

ou:

```text
https://raw.githubusercontent.com/AlexPiresFerreira/Fortigate/main/blocked-domains.txt
```

Não utilize:

```text
https://SEU_PAT@raw.githubusercontent.com/...
```

Nem:

```text
https://raw.githubusercontent.com/.../arquivo.txt?token=SEU_PAT
```

---

## 6. Teste do acesso ao GitHub

Antes de configurar o FortiGate, teste o arquivo em um terminal:

```bash
curl -i -u 'AlexPiresFerreira:SEU_PAT' \
'https://raw.githubusercontent.com/AlexPiresFerreira/Fortigate/main/allow-ip.txt'
```

Para o arquivo de domínios:

```bash
curl -i -u 'AlexPiresFerreira:SEU_PAT' \
'https://raw.githubusercontent.com/AlexPiresFerreira/Fortigate/main/blocked-domains.txt'
```

O resultado esperado deve conter:

```text
HTTP/2 200
```

Em seguida, deve aparecer o conteúdo do arquivo.

### Principais erros

| Erro | Possível causa |
|---|---|
| `curl: (3)` | URL ou sintaxe incorreta |
| `401 Unauthorized` | Usuário ou PAT incorreto |
| `403 Forbidden` | PAT sem permissão, expirado ou revogado |
| `404 Not Found` | Repositório, branch ou arquivo incorreto |
| Timeout | Problema de rota, DNS, proxy ou firewall |

## 7. Configuração do Threat Feed no FortiGate

Acesse:

```text
Security Fabric → External Connectors
```

Crie um novo conector.

### Feed de IP

Configure:

```text
Type: IP Address Threat Feed
Name: ALLOW-IP
URL: https://raw.githubusercontent.com/AlexPiresFerreira/Fortigate/main/allow-ip.txt
```

Habilite:

```text
HTTP Basic Authentication
```

Informe:

```text
Username: AlexPiresFerreira
Password: SEU_PAT
```

Esse feed deve conter somente IPs e redes CIDR.

### Feed de domínio

Se a versão do FortiOS disponibilizar esse tipo de conector, configure:

```text
Type: Domain Name Threat Feed
Name: BLOCKED-DOMAINS
URL: https://raw.githubusercontent.com/AlexPiresFerreira/Fortigate/main/blocked-domains.txt
```

Habilite também:

```text
HTTP Basic Authentication
```

Depois, force uma atualização do conector e confirme:

- status da conexão;
- data da última atualização;
- quantidade de entradas importadas;
- mensagens de erro.

## 8. Uso do Threat Feed no DNS Filter

### Feed externo de IP

A opção:

```text
External IP Block Lists
```

aceita um:

```text
IP Address Threat Feed
```

Exemplo válido:

```text
1.1.1.1
3.3.3.3
```

Não utilize nessa opção:

```text
uol.com.br
gpoaccess.com
```

O FortiGate não transforma automaticamente os domínios em IPs nessa função.

### Bloqueio de domínios pelo DNS Filter

No FortiGate, acesse:

```text
Security Profiles → DNS Filter
```

Edite ou crie um perfil.

Ative:

```text
Domain Filter
```

Adicione os domínios manualmente:

```text
uol.com.br
www.uol.com.br
gpoaccess.com
```

Na ação, utilize:

```text
Redirect to Block Portal
```

No FortiOS utilizado no laboratório, o bloqueio de domínios foi validado pelo **Static Domain Filter**.

---

## 9. Ação global do DNS Filter

O comportamento geral do bloqueio pode ser configurado pelo CLI.

### Redirecionar para o portal de bloqueio

```text
config dnsfilter profile
    edit "NOME_DO_PERFIL"
        set block-action redirect
    next
end
```

### Retornar NXDOMAIN

```text
config dnsfilter profile
    edit "NOME_DO_PERFIL"
        set block-action block
    next
end
```

O cliente receberá uma resposta indicando que o domínio não existe.

### Retornar SERVFAIL

```text
config dnsfilter profile
    edit "NOME_DO_PERFIL"
        set block-action block-sevrfail
    next
end
```

O cliente receberá uma falha na resolução DNS.

## 10. Aplicação do DNS Filter à política

Acesse:

```text
Policy & Objects → Firewall Policy
```

Edite a política que permite o acesso da rede interna à Internet.

Na seção de perfis de segurança:

1. Habilite **DNS Filter**;
2. Selecione o perfil criado;
3. Salve a política.

A configuração deve ficar semelhante a:

```text
LAN → WAN
DNS Filter: DNS-BLOQUEIO
```

---

## 11. Garantir que o DNS passe pelo FortiGate

O DNS Filter somente funcionará se as consultas dos clientes passarem pelo FortiGate.

Verifique se os clientes recebem o FortiGate como servidor DNS via DHCP.

No Windows:

```powershell
ipconfig /all
```

Confira o campo:

```text
DNS Servers
```

Também é recomendável:

- bloquear DNS externo via UDP/53;
- bloquear DNS externo via TCP/53;
- impedir o uso direto de `8.8.8.8` e `1.1.1.1`;
- avaliar o bloqueio de DNS over HTTPS (DoH);
- avaliar o bloqueio de DNS over TLS (DoT).

---

## 12. Teste no cliente

Limpe o cache DNS:

```powershell
ipconfig /flushdns
```

Teste a resolução:

```powershell
nslookup gpoaccess.com
```

Depois tente acessar o domínio pelo navegador.

Resultado esperado:

- `redirect`: redirecionamento para o portal de bloqueio;
- `block`: resposta `Non-existent domain`;
- `block-sevrfail`: falha na resolução DNS.

Verifique os logs em:

```text
Log & Report → DNS Filter
```

Também confira os logs da política de firewall.

---

## 13. Diagnóstico no FortiGate

Teste a conectividade do FortiGate com o GitHub:

```text
execute ping raw.githubusercontent.com
```

Confira a tabela de rotas:

```text
get router info routing-table all
```

Verifique:

- existência de rota default;
- DNS configurado;
- data e hora corretas;
- acesso à porta TCP/443;
- ausência de proxy obrigatório;
- política de saída permitindo o acesso do FortiGate.

O fato de o `curl` funcionar em um computador não garante que o FortiGate tenha acesso ao GitHub. O FortiGate precisa ter sua própria rota, DNS e conectividade com a Internet.

---

## 14. Boas práticas

- Mantenha feeds separados para IPs e domínios.
- Use nomes claros, como `allow-ip` e `blocked-domains`.
- Não misture comentários, IPs e domínios no mesmo arquivo.
- Utilize um PAT exclusivo para o FortiGate.
- Dê ao PAT somente a permissão `Contents: Read-only`.
- Defina uma data de expiração para o PAT.
- Revogue o PAT se ele for exposto.
- Gere um novo PAT antes de utilizar o ambiente em produção.
- Não use o arquivo de domínios no `External IP Block Lists`.
- Faça alterações pequenas e valide pelos logs.
- Documente a URL, o nome do conector e a data de expiração, mas nunca o valor do PAT.

## Resumo da arquitetura

```text
GitHub
   │
   ├── allow-ip.txt
   │       └── IP Address Threat Feed
   │
   └── blocked-domains.txt
           └── Domain Name Threat Feed
                   ou Static Domain Filter
                           │
                           ▼
                    Perfil DNS Filter
                           │
                           ▼
                    Política LAN → WAN
                           │
                           ▼
                         Clientes
```

## Regra principal

- **Feed de IP:** contém IPs e redes CIDR.
- **Feed de domínio:** contém nomes de domínio.
- **External IP Block Lists:** aceita feed de IP.
- **Domain Filter:** utilizado para bloquear domínios no DNS Filter.
- **PAT:** usado somente na autenticação HTTP Basic do conector.
