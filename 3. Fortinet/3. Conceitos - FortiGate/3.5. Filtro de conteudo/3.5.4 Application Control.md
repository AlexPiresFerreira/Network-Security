## Objetivo

O **Application Control** identifica e controla aplicações que atravessam o FortiGate, como Microsoft Teams, BitTorrent e Google Meet.

Ele usa o **IPS Engine** para comparar o tráfego com assinaturas de aplicações. Com base no perfil configurado, o FortiGate pode permitir, monitorar ou bloquear as aplicações identificadas.

O Application Control complementa os demais perfis de segurança. **Permitir uma aplicação no Application Control não garante que todo o tráfego será liberado**: outros controles, como Web Filter e IPS, ainda podem analisá-lo e aplicar suas próprias ações.

## Como funciona

O Application Control analisa padrões conhecidos de comunicação para identificar aplicações. Ele pode reconhecer tráfego mesmo quando a aplicação usa:

- Portas padrão ou não padrão.
- Protocolos de rede conhecidos.
- Protocolos ou métodos de comunicação reutilizados por outras aplicações.

A identificação é mais confiável quando a aplicação possui um padrão de tráfego próprio. Algumas aplicações compartilham protocolos e métodos de comunicação, o que pode limitar a precisão da identificação.

Por exemplo, um jogo pode usar BitTorrent para distribuir atualizações. Isso não significa necessariamente que o tráfego observado seja uma sessão convencional de compartilhamento de arquivos.

### Relação com o IPS Engine

- O **IPS Engine** realiza a identificação das aplicações.
- O Application Control pode ser configurado em políticas Flow-Based ou Proxy-Based.
- Mesmo quando a política está em modo Proxy-Based, a inspeção do Application Control é realizada pelo IPS Engine em **Flow-Based**.

## Assinaturas e categorias

As assinaturas do Application Control são organizadas em categorias e podem ter uma estrutura hierárquica.

- Uma assinatura **pai** tem precedência sobre suas assinaturas **filhas**.
- Uma categoria pode conter várias aplicações.
- O perfil pode aplicar ações a categorias inteiras ou a aplicações específicas.
- Também é possível definir o comportamento para aplicações não reconhecidas.

A base de assinaturas é atualizada pelo FortiGuard, conforme a licença e as atualizações disponíveis no equipamento.

## Ordem de avaliação

O perfil avalia as regras nesta ordem:

1. **Application and Filter Overrides** — regras específicas para aplicações e filtros.
2. **Categories** — ações definidas por categoria.

Considere a ordem ao criar exceções: uma regra mais específica avaliada antes pode determinar a ação aplicada ao tráfego.

## Ações

As ações disponíveis dependem da assinatura, do perfil e da versão do FortiOS. A apostila apresenta estes comportamentos:

| Ação | Comportamento |
|---|---|
| **Pass** | Permite o tráfego sem gerar o log correspondente à ação de monitoramento |
| **Monitor** | Permite o tráfego e registra a atividade |
| **Block** | Bloqueia o tráfego e registra o evento |
| **Quarantine** | Bloqueia o tráfego associado ao IP conforme o período de quarentena configurado |

O perfil também pode permitir ações específicas para:

- Todas as categorias.
- Uma categoria.
- Uma aplicação individual.
- Um grupo de aplicações.
- Aplicações não reconhecidas.

## Opções adicionais

Dependendo da versão e da configuração, o perfil pode oferecer opções para:

- Controlar serviços conhecidos que usam portas diferentes das esperadas.
- Bloquear aplicações que não utilizam portas padrão.
- Definir protocolos e critérios adicionais de inspeção.
- Exibir páginas de bloqueio para aplicações HTTP-based.

A opção **Replacement Messages for HTTP-Based Applications** permite apresentar uma página de bloqueio para aplicações compatíveis. A mensagem pode ser personalizada em **System > Replacement Messages**.

## Inspeção SSL

Algumas assinaturas de aplicação precisam examinar tráfego criptografado para serem identificadas corretamente.

- O tráfego SSL pode exigir um perfil de inspeção SSL apropriado.
- Algumas assinaturas avançadas indicam a necessidade de **Deep Inspection**.
- O ícone de cadeado ao lado de uma aplicação no perfil pode indicar essa necessidade.
- A Deep Inspection pode afetar aplicações que usam TLS/SSL; avalie compatibilidade, certificados e exceções.

Ver também: [[351_Certificados]].

## Aplicação em política de firewall

Para aplicar Application Control:

1. Crie ou selecione um perfil de Application Control.
2. Configure ações para aplicações, filtros ou categorias.
3. Edite a política de firewall correspondente.
4. Ative **Application Control** na política.
5. Selecione o perfil.
6. Habilite os logs necessários.
7. Configure a inspeção SSL caso determinadas assinaturas exijam análise de tráfego criptografado.

O perfil só é aplicado ao tráfego que corresponde à política de firewall.

## Interação com outros perfis

Os perfis de segurança podem atuar em conjunto:

- Uma aplicação permitida no Application Control ainda pode ser bloqueada pelo **Web Filter**.
- O Web Filter aplica suas próprias verificações e pode apresentar uma página de bloqueio diferente.
- A ação `Exempt` do filtro estático de URL do Web Filter não libera uma aplicação bloqueada pelo Application Control, pois o Application Control é avaliado antes do Web Filter no fluxo descrito na apostila.
- O **IPS** também pode detectar e bloquear ameaças no tráfego, independentemente da ação do Application Control.

> A ordem exata e o comportamento podem depender do fluxo de inspeção e da configuração da política. Consulte os logs dos perfis envolvidos para identificar qual controle tomou a ação.

## Logs e monitoramento

Os eventos podem ser consultados em:

**Log & Report > Security Events > Application Control**

Os logs podem incluir:

- Nome e categoria da aplicação.
- Ação executada.
- Perfil aplicado.
- Política associada.
- Protocolo e serviço.
- Informações de risco.
- Endereços de origem e destino.

O FortiView também permite explorar aplicações e sessões:

**Dashboard > FortiView Applications**

É possível analisar aplicações identificadas, sessões e volume de tráfego.

## Troubleshooting

Se o Application Control não identificar ou controlar uma aplicação como esperado:

1. Confirme que o perfil está ativado na política de firewall correta.
2. Verifique se o tráfego realmente corresponde à política.
3. Confira a assinatura, a categoria e a ação configuradas.
4. Revise a ordem das regras em **Application and Filter Overrides** e das categorias.
5. Consulte os logs de Application Control e identifique a ação aplicada.
6. Use o FortiView para confirmar se o tráfego foi classificado como a aplicação esperada.
7. Verifique se o tráfego criptografado exige Deep Inspection.
8. Revise os outros perfis de segurança: Web Filter, IPS e Antivírus podem aplicar ações independentes.
9. Evite inspecionar tráfego desnecessário; identifique a política correspondente e ajuste o perfil de forma controlada.

## Resumo

- O Application Control identifica aplicações usando assinaturas processadas pelo **IPS Engine**.
- Pode controlar aplicações por regra individual, filtro, categoria ou comportamento para aplicações desconhecidas.
- As assinaturas são avaliadas primeiro em **Application and Filter Overrides** e depois em **Categories**.
- Assinaturas pai têm precedência sobre assinaturas filhas.
- Uma aplicação permitida pode continuar sujeita ao Web Filter, IPS e outros perfis.
- Algumas assinaturas exigem **Deep Inspection** para identificar tráfego criptografado.
- Os logs ficam em **Security Events > Application Control**; o FortiView ajuda a examinar aplicações e sessões.
